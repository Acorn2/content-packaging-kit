# 联网增强与动态样本

## 何时启用

完整爆款包、陌生题材或用户反馈平淡 / 重复时，默认做轻量公开标题参考检索；用户要求“联网增强”“参考近期同类内容”“找热门标题”“结合最新数据”“核实平台规则”时按对应问题深入。用户要求完善 Skill / 扩展参考时，同时搜索类似 GitHub 项目。单句润色可复用本地方法，不强制每次登录后台或购买数据。

先读取 [来源库](source-library.md)，按问题选择来源：平台字段查官方入口，表达参考先看具体标题，创意方法查公开原文和项目相关文件，标题实验查原论文，同题材表达查真实作品，账号效果查用户提供的自有数据。

公开方法文章与 GitHub 项目按 [参考扩展](reference-expansion.md) 搜索、读取和迁移；记录方法如何改变候选，GitHub 另记 revision、相关文件和许可状态。下方作品采样数量、近期窗口和互动字段只用于真实作品研究，不要求每篇方法文章带播放数据，也不将作者模板冒充已观察的热门作品。

用户明确不联网时遵循该要求，推荐理由仅为编辑判断。具体事实以原始文档及获准使用的产品资料为依据，创意表达不受原句限制；网上材料帮助寻找动机和表达，不让热点改变作品实际覆盖。

## 研究问题与检索

1. 从文档确定题材、发布形式及 2–4 个核心关键词，寻找受众会怎样提问；不要先搜无关的“通用爆款标题”。
2. 平台规则优先官方域名：知乎 `zhihu.com`，抖音 `douyin.com`，小红书 `xiaohongshu.com`，B站 `bilibili.com`，视频号 `weixin.qq.com` / `qq.com`。在这些域名发布的普通用户文章并不自动是官方指南，仍需核对发布主体。
3. 相似内容用“平台 + 核心关键词 + 问题 / 对比 / 教程 / 历史”等搜索，并打开原作品。跨平台搜索结果可能缺少日期或互动数，不能把摘要当完整样本。
4. 论文查原始论文、开放存档与作者数据说明；营销转载只作发现线索。
5. 有合适浏览器 / 连接器时用当前可用能力；登录入口不可达则记录缺口，继续公开研究，不要求上传视频或解析字幕。

## 最小采样

每个重点平台以 3–5 条同题材、同形式公开作品作为小样本目标，尽量包含不同作者及表现普通的对照，避免只取头部爆款。用户只研究一个平台就只采该平台。此数量是成本控制建议，不构成统计代表性。

- 优先最近 30 天；不足时扩展到 90 天并说明。题材不追热点时可以采用更早的相关样本，保持日期标签。
- 每条记录：平台、真实 URL、题材、形式、标题、作品发布日期、观察时间、实际可见指标及口径；可见时补作者规模、封面文字、时长或图卡数量。
- 缺失指标填写“未公开 / 未取得”；预估指标标明预估及来源。不可从排名反推点击量，也不可猜测作者后台数据。
- 没打开作品、只看到搜索摘要的记录标为“搜索线索”，不计入已观察样本。
- 只有标题和点赞的样本，只能帮助发现表达模式，不能证明点击效果或当前算法权重。
- 没有样本也可以生成文案，明确该平台未取得动态证据，不用虚构案例补齐数量。

## 提炼与选择

提取对象是否清楚、关键词位置、悬念位置、冲突 / 利益点、封面与标题分工。区分“观察到的共同点”和“已证实的作用”；若作品的题材、封面、作者规模或投流情况不同，不把表现差异归因于标题。

在具体事实与内容承诺可兑现的范围内尝试：

- 信息明确且使用常见词的版本；
- 对象明确、只留一个关键原因或结果的悬念版本；
- 原文有依据的代价、反差或利益版本。
- 场景代入、体验比喻和更鲜明的情绪版本；不是照搬样本作者的经历。

这些是候选方向，不能强制每次三种都出现，也不能照搬样本的经历、数字或人名关系。用户想要三个结果时交付三个，但可在内部尝试更多。

## 自有数据与对照

用户提供真实记录后，区分标题版本、封面版本、发布时间、观察窗口、曝光、点击、播放、阅读 / 完播及互动。缺少某项时保持缺失。

CTR 仅在点击与曝光属于相同口径、同一观察窗口时计算；曝光为零时记为不适用。推荐流自动播放场景的播放 / 曝光不自动等于标题点击率。连续发布两篇或前后更换标题不天然是随机 A/B 实验，需说明时间、题材与分发因素。

不要为了做测试自动重发作品、改标题或访问私人后台；在本任务内仅分析用户提供或公开可读的资料。

## 输出与保存

联网增强的发布包末尾增加“研究依据”，与可复制文案分开：

- 本次关键词、平台、时间范围、实际取得样本数；
- 采用的来源 URL、发布日期或数据期、访问时间、读取范围；
- 可迁移的表达判断及其对应候选；
- 缺少的指标、不可达来源、推断边界。

解释“本次采用了什么”即可，不将所有来源列表塞入每个平台配文。有原作品链接且确实取得的数据时，样本记录另存为发布包旁 `<原文名>-research.md`；重名规则沿用 SKILL.md。不批量下载媒体或存放受限商业数据，不把研究记录写成已完成发布。

生成期间不修改本 Skill 的来源库；只有用户明确要求“更新来源 / 完善 Skill”时才更新维护记录。新增来源必须实际访问，按 [来源库](source-library.md) 的状态与时间口径登记；不能仅依据搜索排序加入“已验证”标识。
