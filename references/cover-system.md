# 固定模板与封面定稿

本流程借鉴品牌包、不同创意比较与小尺寸检查的方法；维护依据见 [来源库](source-library.md#封面项目参考)。本项目独立实现轻量渲染器，没有引入外部完整应用。

## 输入

`brand.json` 固定色板、署名、本地字体及 SHA-256、4:3 / 3:4 画布尺寸、字号、安全边距、分类区、文字区、主体区和署名区。示例：[Hresh品牌配置](../examples/cover-system/nature-museum/brand.json)。其他账号使用自己的配置，不默认署名 Hresh。

品牌名属于输入，署名的字体、位置和大小属于模板。用户可以在对话中说“封面品牌名用『星河工作室』”，Agent 将该名称通过 `--signature "星河工作室"` 传入渲染器；本次输入优先于 `brand.json` 的 `signature`，不会改写源品牌配置。用户说“不要署名”时传入 `--signature ""`，同时移除文字和前方蓝色短线。未传参数时沿用品牌配置；没有明确品牌或已确认账号规范时，Agent 应显式传空值，避免误用示例署名。

自定义名称原样作为文字渲染（仅去除首尾空格），不执行其中的 HTML。名称须为单行；过长超出固定署名区域时停止并提示改短，不临时缩字号。生图不负责生成品牌文字。实际使用的署名保存到输出 `brand.json` 和 `render-report.json`，重放及定稿沿用该次署名。审阅页展示已渲染图片；修改署名后需重新渲染，再下载两版图片。

用户只要求修改品牌名时，复用已有输出的 `request.json`、`brand.json` 和主体素材，增加 `--signature` 并渲染到新目录；保留原图、主句及其他发布字段，不重新生图。

`request.json` 提供一至六个候选，包含 `id`、两行 `headline`、`category`、`subhead`、点击理由 `reason`、本地素材 `asset`、`layout`，以及可选的编辑主推 `recommendedId`。用户已选视觉参考时，默认只提供一个标准方向。支持 `object`（主题主体）、`window`（网页隐喻，需有来源的 `domain`）和 `people`（人物情境）；可选 `secondaryAsset` 用于第二个主体，需要在品牌配置中提供 `secondaryHero` 区域。例：[图1风格标准封面](../examples/cover-system/nature-museum/request.json)。

不要把栏目、题材、用户身份或网站域名写成全局模板默认事实。浏览器外框只是视觉隐喻，不能称为真实产品界面。图像只接受本地 PNG / JPEG / WebP，避免渲染时请求外部素材。

人物与标识由 Agent 先按 [主体与账号识别决策](cover-design.md#内容主体与账号识别) 选择，渲染器只执行已选素材和配置。`layout: "people"` 表示人物情境，不代表每期需要本人出镜；`secondaryAsset` 是第二个内容主体，不是默认头像位。`signature` 仅控制文字署名，提供品牌名不等于要求附加头像、Logo 或固定角色。需要人物与产品共同表达时，先核对现有区域和素材是否适用；不能为了套模板退回内容无关的大头照或用署名字段冒充图片能力。

## 跨题材共用的排版

所有题材的横竖封面共用同一套标题语言：两行主标题与黄色重点底线整体固定旋转 **−2°**，向右上方轻扬；栏目、辅助说明和署名保持水平。倾角由 HTML 模板固定，不按视频题材随机调整，也不逐字旋转。保留固定字号、配色和区域布局，主体在指定区域内按比例容纳。标题文字有微小的固定水平内移，以保持旋转后的字体边界处于安全范围；标准主体区左侧保留 12px 内边距，留出图文间隔。

内容变化只替换主句、重点短语、栏目、辅助说明和有依据的主体素材。亲子插画不是模板必备元素：AI、产品、教程等内容沿用同一排版骨架，按素材类型使用插画、真实截图或照片，不把一个视频中的动物、角色或装饰移植到全部题材。

## 固定字号，而不是遇到长句就缩字

字号先按参考校准，再固定；112px是前轮排版起点，不能为了守住它而丢失用户满意参考的视觉占比。当前标准封面横版普通行142px、强调行196px，竖版普通行162px、强调行196px，主标题均为900字重；辅助36px / 500、栏目28px / 600、署名26px / 600。72px安全边距；这些是内部编辑配置，不是平台规则。

`emphasisSize`、`signatureSize`、`headlineLeading`、`copyGap` 分别控制强调行字号、署名字号、行距与辅助句间距，未提供时兼容旧配置。可选 `arrow` 区域只显示同一款细蓝虚线箭头，不随机添加射线、感叹笔触或新贴纸。原始画布独立排版，展示时整体缩略；固定交付1600×1200与1200×1600。

标题过长导致溢出时，优先删字或在两行间重新分配；确定修改账号模板时更新其配置版本并重渲染。不得逐条随意改字体或字号。文件指纹不符则停止，不能使用系统字体代替。

## 渲染

环境需要已有 Node.js、Playwright 与 Chromium。标题任务不需要这些依赖；缺失时说明，未经授权不安装。可利用宿主提供的依赖路径：

```bash
node scripts/render_covers.mjs \
  --request examples/cover-system/nature-museum/request.json \
  --brand examples/cover-system/nature-museum/brand.json \
  --signature "星河工作室" \
  --out-dir outputs/nature-museum-cover-review \
  --modules <existing-node_modules-path>
```

当前环境已能通过 Node 解析 Playwright 时，省略 `--modules`。有空格的路径加引号。脚本只创建新目录，重名则失败；用新版本目录重试，旧成图与失败报告均保留。

输出包含每个方向的双比例 PNG 与可编辑 HTML、`review.html`、缩略预览、字体及许可、素材、可重放品牌与请求配置、`render-report.json`。一个方向时页面直接并排展示横竖两版；多个方向时才启用候选比较。报告包含字体、模板、品牌、两层素材和PNG指纹、浏览器版本及实际边界检查；技术通过不等于创意有效。

透明素材可以与文字区的外接矩形部分交叠，但可见像素必须避开文字。模板按旋转后的文字矩形四角和实际 object-fit 绘制位置检查素材 Alpha，避免将倾斜文字外接框的空白角误判为遮挡；安全边距和溢出检查也使用变换后的边界。不能仅为满足矩形不相交而缩小主体。人工检查仍需确认两个主体彼此不遮挡、画面占比忠于参考。渲染报告的 `headlineAngle` 记录实际标题角度。

正式渲染使用仅绑定回环地址的临时服务器，阻断外部资源请求；完成后关闭。对外预览另用静态服务器，不需要后端或账户。

## 比较与选择

把输出目录通过本地静态服务器打开，实际检查：

- 有明确参考时先检查标准封面是否忠实，不默认展开三个方向。探索多个方向时再比较观看理由；把纯知识问句用于资源推荐时，检查是否丢失“这是网站”的信息。
- 切换 4:3 / 3:4，分别检查文字与主体，不裁切另一比例。
- 缩到 180×240 / 240×180，检查主句、主体及账号识别。署名和辅助说明可以是次要信息，不能依靠它们才认出主题。
- 按本条选定路线检查人物是否参与内容表达、品牌标记是否抢占主题；缩略后难读的署名不能单独证明账号可辨认，不为补足识别而自动加头像。用户明确指定的标识按其规范保留。
- 灰度检查结构，时长叠层检查右下角；两者为内部模拟，不宣称已核实平台当前裁切区。
- 有真实已发布邻图时可另做主页混排；只有一个视频的多个候选时只能称候选比较。

页面默认没有用户最终确认；单方向页面可“标记本版可用”，多方向页面可“选择这一方向”，随后下载 `selection.json`。“编辑主推”只是建议。用户在对话明确确认时，Agent也可据该明确请求创建记录并注明来源，不得自行把编辑推荐冒充用户确认。

## 定稿导出

```bash
node scripts/finalize_cover.mjs \
  --review <review-directory> \
  --selection <user-selection.json> \
  --out-dir <new-final-directory>
```

定稿工具验证选择属于该批候选、该批渲染成功、两张 PNG 的检查及指纹、实际宽高；素材在渲染后被改过则要求重渲染。输出纯封面和选择 / 定稿记录，不上传内容，不覆盖比较目录。脚本不能核实是谁写了记录，Agent仍须以用户明确选择为依据。

验证入口：`node scripts/test_cover_system.mjs --modules <existing-node_modules-path>`，结果保留在已忽略的 `.tmp/`。验证记录不能把测试选择当成用户真实定稿。
