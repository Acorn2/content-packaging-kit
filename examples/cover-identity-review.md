# 封面主体与账号标识：决策示例

以下均为假设输入与策划预期，用于复核 [主体与账号识别决策](../references/cover-design.md#内容主体与账号识别)，不是已发布案例或传播效果测试。不依赖 Hresh 的人设、配色、人物或宠物。

## 非原示例题材：厨房备菜

假设输入：视频完整展示提前准备三份晚餐的过程与成品；用户只给视频，没有品牌名、头像或账号规范，要求封面。

- 路线：内容主体主导，以三份实际晚餐成品为主角，准备过程作可选辅助，不为“个人品牌”新增厨师头像。
- 主句：`三份晚餐\n提前备好`，去掉排版换行共 8 字。“三份”由假设原视频承接，不新增省钱、减脂或节省时长承诺。
- 标识：无明确品牌名和账号规范，不署名、不复制示例账号；先采用适合食物的字体与配色关系，记录为本次方案，不宣称已建立受众认知。
- 固定模板执行：选实际成品素材使用 `object`；Agent 显式传入 `--signature ""`。渲染器不会因为素材中有人就自动加头像。
- 交付：按请求生成封面及缩略预览；在 `cover-notes.md` 简记路线与省略标识的理由。此示例未提供真实视频，不声称已经取材或生成成品。

## 人物有表达作用：陶艺实作

假设输入：创作者提供本人真实制作杯子、发现裂痕的照片与视频，主题是一次失败复盘；观众尚不认识创作者。

- 路线：人物与内容结合，优先展示本人手持裂杯查看的真实画面。人物在呈现经历与动作，不因陌生观众尚不认识本人而一律删掉。
- 主句：`我把杯子\n做裂了`，去掉换行共 7 字，由假设素材中的本人经历承接。
- 标识：无需再贴同一人的圆形头像；是否署名依用户输入和规范决定，不能把不署名等同于不建立个人账号。
- 缺失路径：如果用户明确要求本人作为主角，却只提供杯子照片，说明缺少本人素材，可先交策划；不生成假冒本人制作失败的照片，不换成陌生面孔。

## 边界场景复核

| 假设请求 | 应作出的决定 | 不应出现的行为 |
| --- | --- | --- |
| 不露脸的天文动画系列，已有配色与插画规范 | 内容对象主导，沿用系列语言 | 为了“做 IP”强加真人脸或借用别人的吉祥物 |
| 工具教程要求品牌名“星河工作室”，未要求头像 | 突出操作与结果，按输入设置文字署名 | 把品牌名视为新增 Logo、头像或固定角色的授权 |
| 产品复盘已有本人、产品素材，主句“这个按钮，我删掉了” | 判断人物与被删功能之间的表达关系，选择人物与内容结合或内容主导，并说明理由 | 只按“产品”关键词排除本人，或凭照片虚构产品成绩 |
| 账号规范明确每期保留左上角头像，本次只补封面 | 保留确认过的头像，控制其层级，复用用户素材 | 以默认内容主导为由擅自删除头像、换色或重写已选文案 |
| 用户明确不要署名 | 传空署名，移除署名及关联装饰，仍可保持已确认的视觉语言 | 为了账号识别偷偷恢复名字或新增替代 Logo |
| 用户只要求把署名改成“星河工作室” | 只更新文字署名，复用主体和构图 | 重选人物、加头像或重做文案 |
| 用户只要两个平台的标题 | 进入标题流程，不读取视频、渲染封面或追问头像资料 | 品牌策略将普通标题任务升级为封面制作 |
| 用户只补小红书封面，其他平台和发布字段已选好 | 仅处理请求的封面及说明，保留其他字段 | 顺带改其他平台标题、简介、标签和排期 |

主句“这个按钮，我删掉了”按 Unicode 码点计 9 字，含逗号；未声明平台硬限制。计数仅核对文本，不证明创意有效。

## 人工缩略检查

有实际成图后再检查：隐藏发布标题是否能理解本条内容；人物是否在表达主题；额外头像、Logo 或固定角色是否抢走主角；已确认的系列特征是否仍可辨认。署名在文件中存在但缩小后不可读，不能据此判定账号识别成立；也不能靠一味放大署名弥补。

多个真实选题可做并排观察；同一作品的候选比较、用户选择和发布效果分开记录。没有曝光与观看数据，不把“有脸 / 无脸”“有 Logo / 无 Logo”说成已经验证的增长策略。
